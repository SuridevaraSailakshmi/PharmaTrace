# PHARMATRACE LABEL AND QR FORMAT

## SECTION A — HUMAN-READABLE LABEL FORMAT

The visual downloadable label generated by PharmaTrace is explicitly designed to match the provided pharmaceutical reference image exactly.

**Visual Source of Truth:**
- Matches the precise layout, dimensions, typography, and borders of the initial product reference image.
- **Dimensions / Layout:** Boxed layout with a thick outer border. Divided into left (Product Metadata) and right (Weights & QR) sections.
- **Visible Fields:**
  - Product Name
  - Batch No.
  - License No.
  - CAS No.
  - Mfg. Date
  - Re-test/Expiry Date
  - Container No.
  - Country of Origin
  - Storage
  - Manufactured By (including full Address block)
  - Gross Weight
  - Tare Weight
  - Net Weight
- **Fields explicitly omitted from label text:** SSCC.
- **PRC Placement:** The Product Reference Code (PRC) is rendered visibly in the bottom left section (below the reference code line `WH/SOP/011/F-03/07-01-01-2025`).
- **QR Placement:** Rendered strictly on the bottom right side.

## SECTION B — QR PAYLOAD FORMAT

The encoded data embedded inside the QR Code utilizes the deterministic PharmaTrace JSON payload contract. 

**Payload Definition:**
The QR does not store raw strings; it contains a strictly ordered, versioned JSON object.

**Format Details:**
- **Payload Version (`v`):** Fixed to `1` indicating V1 of the traceability schema.
- **PRC (`prc`):** The exact server-generated, globally unique Product Reference Code.
- **SSCC (`sscc`):** The exact server-generated 18-digit Serial Shipping Container Code.
- **Form Data (`data`):** A nested object containing the remaining required fields (as defined by the published form template configuration's `includeInQr` flag).

**Example Payload Structure:**
```json
{
  "v": 1,
  "prc": "PRC-2026-000001",
  "sscc": "061414100000000018",
  "data": {
    "product_name": "EMPAGLIFLOZIN MICRONIZED IH",
    "batch_no": "KSR04/A-045/001/26",
    "license_no": "49/HD/AP/2004/B/R",
    "cas_no": "915095-99-7",
    "mfg_date": "April 2026",
    "retest_expiry_date": "20/04/2029",
    "container_no": "01/01",
    "country_of_origin": "India",
    "storage": "Store at Ambient Condition",
    "manufactured_by": "ALMELO PRIVATE LIMITED, UNIT-I",
    "manufacturer_address": "Plot No. A-38 & 39, Road No. 7...",
    "gross_weight": "12.00 Kg",
    "tare_weight": "02.00 Kg",
    "net_weight": "10.00 Kg"
  }
}
```

**Generation Source:**
The QR payload string is reliably generated server-side within the `QRPayloadService` and securely tied to the exact committed values of the atomic traceability transaction. The payload string is then converted into SVG/PNG. 

## SECTION C — SEPARATION

The system treats the background Traceability Record vs the Human-Readable Downloadable Label as distinct artifacts serving different compliance rules.

**SSCC Handling:**
- **Database:** YES (Persisted in `sscc_records` and `qr_records`)
- **Traceability Record Transaction:** YES 
- **QR Payload:** YES (Scannable by machines)
- **Visible Downloaded Label Text:** NO (Explicitly excluded to match reference formatting and prevent human mis-keying).

**PRC Handling:**
- **Database:** YES
- **Traceability Record Transaction:** YES
- **QR Payload:** YES
- **Visible Downloaded Label Text:** YES (Displayed alongside the QR).
